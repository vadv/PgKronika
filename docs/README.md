# Документация PgKronika

Этот каталог содержит документацию о текущем поведении PgKronika. Начните с
корневого [`README.ru.md`](../README.ru.md), если нужно установить и запустить
проект, или с [`architecture.md`](architecture.md), если нужно понять границы
компонентов и путь данных.

## Карта документов

| Задача | Документ |
| --- | --- |
| Понять процессы, компоненты и зависимости | [`architecture.md`](architecture.md) |
| Настроить подключения к PostgreSQL и сбор по базам | [`connection-and-multidb.md`](connection-and-multidb.md) |
| Запустить локальные проверки и понять CI | [`testing.md`](testing.md) |
| Написать или проверить BDD-сценарий | [`bdd-testing-guide.md`](bdd-testing-guide.md) |
| Разобрать ответ `/v1/incidents` | [`incident-analysis.md`](incident-analysis.md) |
| Найти `type_id`, схему или семантику секции | [`type-registry.md`](type-registry.md) |

Подробные руководства по отдельным компонентам находятся рядом с кодом:

- [`kronika-format`](../crates/kronika-format/README.ru.md) — физическая
  разметка PGM, словари и восстановление `active.parts`;
- [`kronika-registry`](../crates/kronika-registry/README.ru.md) — роль реестра,
  версии схем, строки, счётчики и полнота снимков;
- [`kronika-analytics`](../crates/kronika-analytics/README.ru.md) — разности,
  поиск аномалий и параметры анализа;
- [`pg_kronika-collector`](../bins/pg_kronika-collector/README.ru.md) —
  переменные окружения и расписание сбора;
- [`pg_kronika-web`](../bins/pg_kronika-web/README.ru.md) — HTTP API,
  ограничения запросов и эксплуатация веб-процесса.

## Источники истины

Документ объясняет систему, но не переопределяет код. При расхождении
приоритет такой:

1. структуры, константы и проверки в коде;
2. тесты, которые фиксируют наблюдаемое поведение;
3. README компонента, которому принадлежит контракт;
4. объясняющие документы из этого каталога;
5. исторические проектные записи.

Для `type_id`, столбцов и кодеков источником истины служит
[`kronika-registry`](../crates/kronika-registry/src/lib.rs). Для переменных
окружения коллектора — [`config.rs`](../bins/pg_kronika-collector/src/config.rs).
Для HTTP-ответов — обработчики и проверки в
[`pg_kronika-web`](../bins/pg_kronika-web/src/).

## Исторические и проверочные материалы

Каталог [`superpowers/`](superpowers/) хранит датированные проектные записи.
Они объясняют, почему принималось решение, но могут описывать промежуточное
состояние или отклонённый вариант.

Каталог [`qualification/`](qualification/) содержит критерии и результаты
квалификационных проверок. Это не руководство оператора и не описание всей
архитектуры.

Незавершённые идеи не должны находиться в корне `docs` под видом действующей
справки. Для них используются issue, датированная проектная запись или явно
помеченный квалификационный документ.

## Правила обновления

- Описывайте реализованное поведение в настоящем времени.
- Не привязывайте действующую документацию к номеру PR или временному этапу
  разработки.
- Не копируйте таблицу параметров или схему целиком, если у неё уже есть
  владелец; дайте ссылку и объясните только смысл, нужный читателю.
- Новая версия секции требует синхронного изменения кода реестра, тестов и
  справочника `type-registry`.
- После удаления или переименования файла проверьте все локальные ссылки и
  сообщения бинарников.
- Для документационной правки выполните:

  ```sh
  git diff --check
  cargo +1.96.0 fmt --all --check
  ```
