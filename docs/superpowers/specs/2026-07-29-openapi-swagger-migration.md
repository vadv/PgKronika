# Перенос web-API на генерируемый OpenAPI и Swagger UI

Дата: 2026-07-29. Базируется на main после #137. Заменяет рукописный
контракт OpenAPI и его тестовый сторожевой аппарат генерацией из кода.

## Задача

Единственный потребитель web-API — сами разработчики: посмотреть, какие
ручки есть, и потыкать их при отладке. Внешних клиентов нет и не
планируется. Сегодня контракт обслуживает воображаемого внешнего
потребителя:

- `bins/pg_kronika-web/openapi.json` — 135 КБ, ведётся вручную;
- `bins/pg_kronika-web/src/tests/problems.rs` — 1204 строки, из них ~1000
  (144 assert-макроса в ~14 функциях `assert_*_schema`) существуют только
  чтобы ловить расхождение рукописного JSON с Rust-реестрами;
- схема `Problem` — discriminated union OpenAPI 3.2.0 с `if/then`-веткой на
  каждый код ошибки.

Две копии истины (Rust-типы и рукописный JSON) плюс аппарат их сверки. Ни
Swagger UI, ни живого списка ручек при этом нет — файл нельзя открыть в
браузере без стороннего инструмента.

Цель: контракт генерируется из кода, Swagger UI отдаётся сервером,
рукописный JSON и его сторожевые тесты удаляются, богатство схем срезается
до стандартного.

## Не цели

- Типобезопасный клиентский кодоген для чужих команд.
- Discriminated union по кодам ошибок с типизированными `params` под
  каждый код. Плоская схема `Problem` достаточна.
- OpenAPI 3.2.0-специфичные конструкции. `utoipa` даёт 3.1 — этого хватает
  для Swagger UI и отладки.
- Полная типизация всех тел ответов в этом PR (см. «Тела ответов»).

## Решение

`utoipa` (code-first генерация из макросов) + `utoipa-axum`
(`OpenApiRouter`, сбор путей из хендлеров) + `utoipa-swagger-ui`
(встроенный Swagger UI). Все три — стандартная индустриальная связка под
axum 0.8; версии фиксируются на актуальные 5.x при реализации.

Источник истины переезжает в код хендлера: атрибут `#[utoipa::path(...)]`
рядом с функцией. Генератор не может разойтись с кодом — сверять нечего.

### Swagger UI под static-musl

Бинарь линкуется статически под `x86_64-unknown-linux-musl`
(`.cargo/config.toml`). Ассеты Swagger UI обязаны быть встроены в бинарь,
а не тянуться с CDN: используется `utoipa-swagger-ui` с фичей `vendored`
(или `utoipa-swagger-ui-vendored`). Сеть в рантайме для UI не требуется.

### Монтаж и взаимодействие со слоями

Роутер `app()` (`lib.rs`) переписывается на `OpenApiRouter`:

- каждый из 18 путей регистрируется через `routes!(handler)`, схема пути
  берётся из его `#[utoipa::path]`;
- `.split_for_parts()` даёт `(Router, OpenApi)`;
- Swagger UI монтируется на `/swagger-ui`, спека — на `/openapi.json`
  (тот же путь, что и сейчас, чтобы не ломать внешние ссылки).

Правила слоёв:

- `/swagger-ui` и `/openapi.json` попадают под тот же basic-auth слой, что
  и `/v1/*` (отладочный доступ к ручкам и их описанию — одна привилегия).
  `/healthz`, `/readyz`, `/metrics` остаются public.
- `static_handler` остаётся fallback'ом; порядок слияния должен оставлять
  явные пути Swagger UI выше SPA-fallback, иначе `/swagger-ui` перехватит
  статика.

## Что удаляется

- `bins/pg_kronika-web/openapi.json` — целиком; заменяется генерируемым в
  рантайме документом.
- Из `problems.rs` — все `assert_*_schema` и обе функции-обхода
  (`openapi_is_a_closed_projection_of_the_machine_registries`,
  `assert_v1_documented_paths` и вспомогательные). Генерация делает сверку
  беспредметной.

## Что остаётся

Поведенческие тесты `problems.rs`, проверяющие рантайм, а не форму
документа, сохраняются и продолжают гонять реальные запросы:

- метод не тот → 405 с `Allow: GET, HEAD`;
- неизвестный query-параметр → `unknown_query_parameter`;
- коды ошибок и их HTTP-статусы соответствуют `ProblemCode`.

Один тест переориентируется вместо удаления: «каждый зарегистрированный
роут присутствует в сгенерированном документе и наоборот». При
`OpenApiRouter` обе стороны строятся из одного источника, поэтому тест
вырождается в дешёвую проверку без рукописного списка — и попутно
закрывает прежнюю дырку (роут без документации).

## Схема Problem

`Problem` становится плоской `#[derive(ToSchema)]`-структурой:

```text
type      string (uri)
status    integer
code      enum ProblemCode
params    object (открытый)
instance  string (uri)
```

`code` — enum, выведенный из `ProblemCode` (единый источник). Ветки
`if/then` под каждый код, типизированные `params` и разбор
`QueryLimitExceeded` по под-условиям — удаляются. Потребителю (свой фронт,
Swagger UI) хватает кода и открытого `params`; при отладке значения видны
как есть.

## Тела ответов

Главная развилка. Сегодня 17 из 18 routed-хендлеров возвращают
`Json<serde_json::Value>` или сырой `Response`, а не типизированные
структуры; единственный типизированный — `ui::handlers::summary`
(`Result<Json<ViewSummaryResponse>, ApiProblem>`). `utoipa` выводит схему
тела только из конкретного типа.

Решение для одного PR: **аннотировать контур, не форсировать типизацию
тел**.

- Все 18 путей получают `#[utoipa::path]` с методом, путём, query-
  параметрами и кодами ответов (200/400/401/404/413/500 по тому, что
  реально отдаёт хендлер) — это даёт Swagger UI полный список ручек,
  параметры и коды, то есть отладочную ценность целиком.
- Тело успешного ответа: где тип уже конкретный (`summary` →
  `ViewSummaryResponse`, будущие типизированные) — `body = Type` с
  `ToSchema`; где `Json<Value>` — тело описывается как открытый `Object`.
  Swagger UI показывает ручку и даёт «Try it out»; точная схема тела
  появляется по мере типизации ответов отдельными шагами, вне этого PR.
- `Problem` как схема ответа для всех кодов ошибок — общая ссылка.

Это честный минимум: список ручек, параметры, коды, рабочий «Try it out»,
Problem-схема. Типизация тел — отложенная работа, не условие миграции, и
не блокирует Swagger UI.

## Query-параметры

Параметры в `#[utoipa::path(params(...))]` должны оставаться проекцией
единого реестра `QueryParameter`, а не второй копией. Реализация выражает
их так, чтобы добавление параметра в реестр отражалось в документе без
ручной правки (общий тип параметров с `IntoParams`, либо генерация списка
из `QueryParameter::ALL`). Рантайм-allowlist роутера и документ обязаны
происходить из одного источника — это проверяет сохранённый поведенческий
тест query-allowlist.

## Объём и границы одного PR

Входит:

1. Зависимости: `utoipa`, `utoipa-axum`, `utoipa-swagger-ui` (vendored).
2. `#[utoipa::path]` на 18 routed-хендлеров; `#[derive(ToSchema)]` на
   `Problem` и на уже типизированный `ViewSummaryResponse`.
3. `app()` на `OpenApiRouter`; монтаж `/swagger-ui` и `/openapi.json` под
   auth; сохранение static-fallback.
4. Удаление `openapi.json` и `assert_*_schema`-тестов; переориентация
   роут-полноты; сохранение поведенческих тестов.

Не входит: типизация `Json<Value>`-тел, любые изменения самого поведения
ручек, новые ручки.

## Тестирование

- Поведенческие тесты `problems.rs` — как есть, зелёные.
- Новый минимальный тест: сгенерированный `OpenApi` парсится, содержит все
  зарегистрированные пути, версия документа ожидаемая.
- Ручная проверка: `/swagger-ui` открывается, показывает 18 ручек,
  «Try it out» на `/v1/version` и `/v1/timeline/health` возвращает ответ.
  Фиксируется скриншотом при сдаче.

## Риски

- `utoipa-axum` привязывает форму роутера; переписывание `app()` — разовое,
  но затрагивает порядок слоёв (auth, fallback, метрики). Слои проверяются
  поведенческими тестами.
- Vendored-ассеты Swagger UI увеличивают размер бинаря на ~1–2 МБ — цена
  автономности под static-musl, приемлемо.
- Смена OpenAPI 3.2.0 → 3.1 и плоский `Problem` меняют наблюдаемую форму
  документа. Внешних потребителей нет, поэтому ломать нечего; фиксируется
  как намеренное сужение контракта.
