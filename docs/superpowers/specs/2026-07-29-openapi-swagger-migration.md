# Простая генерация OpenAPI и Swagger UI

Дата: 2026-07-29. Целевая ветка — актуальный `main`.

## Контекст

Основной потребитель web-API — разработчики PgKronika. API нужен, чтобы
посмотреть маршруты и выполнить запрос при отладке. Внешнего контракта и
клиентского кодогенератора нет.

Сейчас для этого вручную поддерживаются:

- `bins/pg_kronika-web/openapi.json` на 2967 строк;
- сверки JSON со схемами и реестрами Rust в
  `bins/pg_kronika-web/src/tests/problems.rs`;
- закрытый RFC 9457 `Problem` с отдельными URI, дублирующим HTTP-статусом,
  типизированными параметрами и собственным request ID.

Нужно удалить этот аппарат, генерировать простой OpenAPI из аннотаций и
отдать стандартный Swagger UI с рабочим `Try it out`.

## Решение

Добавляются только `utoipa` и `utoipa-swagger-ui` с поддержкой Axum и
vendored-ассетами.

Сохраняется обычный `axum::Router`. `utoipa-axum`, `OpenApiRouter`,
`.split_for_parts()` и собственные генераторы не используются.

Маршруты `/v1/*` получают обычные `#[utoipa::path]`. Список обработчиков
перечисляется напрямую в `#[derive(OpenApi)]`. Query-параметры и коды
ответов указываются непосредственно в аннотациях.

Документ не обязан автоматически совпадать с роутером, runtime-allowlist
или Rust-реестрами. Никаких сверок и генераторов для этого не добавляется.

Точные схемы успешных тел не нужны. Для `serde_json::Value` и сырого
`Response` достаточно открытого JSON-ответа либо кода с кратким
описанием. Уже типизированные ответы не требуют отдельной проработки.

`/healthz`, `/readyz` и `/metrics` остаются вне OpenAPI.

Swagger UI публикуется на `/swagger-ui/`, документ — на
`/openapi.json`. Оба маршрута находятся под тем же Basic Auth, что UI и
`/v1/*`. SPA fallback не должен их перехватывать.

Swagger UI использует встроенные ассеты. CDN и сеть во время работы не
нужны.

## Ошибки API

`Problem` заменяется внутренним `ApiError`:

```json
{
  "code": "unknown_query_parameter",
  "params": {
    "parameter": "locale"
  }
}
```

`code` — строковый машинный идентификатор. `params` — открытый
JSON-объект, пустой для ошибки без параметров.

HTTP-статус остаётся только в статусной строке. Сохраняются необходимые
стандартные заголовки `WWW-Authenticate`, `Allow` и `Retry-After`.
Ответ использует `application/json`.

Удаляются:

- поля `type`, `status` и `instance`;
- `application/problem+json`;
- собственный `x-request-id`;
- URI для кодов ошибок;
- закрытый `ProblemParams` и отдельные структуры параметров;
- RFC 9457-терминология.

OpenAPI описывает `ApiError` как объект со строковым `code` и открытым
`params`. Discriminator, `if/then` и отдельные схемы параметров не нужны.

## Что удалить

1. `bins/pg_kronika-web/openapi.json` целиком.
2. `documented_v1_paths_reach_the_actual_router_with_contextual_allow` из
   `bins/pg_kronika-web/src/tests/problems.rs`.
3. `openapi_is_a_closed_projection_of_the_machine_registries` и все
   вызываемые им `assert_*`.
4. Все проверки версии OpenAPI, `$ref`, закрытости схем, enum-проекций,
   response-схем, путей и query-параметров.
5. Исчерпывающий тест старого `Problem`, тесты request ID и
   locale-neutral Problem Details.
6. BDD-сценарий locale-neutral Problem Details, соответствующий step и
   harness-функцию.
7. Старые структуры и функции `Problem`, не нужные для `{code, params}`.

Взамен не добавляются генераторы, snapshot-файлы или тесты формы OpenAPI.

## Тесты

Тестов OpenAPI и Swagger UI нет. Не проверяются полнота документа,
совпадение с роутером, версия, схемы, сериализация и доступность маршрутов
документации.

Обычные тесты поведения API остаются только там, где проверяют полезное
поведение: HTTP-статус, `code`, нужные `params` и стандартные заголовки.
Проверки удаляемой структуры `Problem` убираются.

## Приёмка

Документация проверяется вручную в demo:

1. Запустить `scripts/demo-stand.sh up`.
2. Открыть `http://127.0.0.1:18081/swagger-ui/`.
3. Выполнить `Try it out` для `GET /v1/version`.
4. Получить реальный ответ с HTTP `200`.

Скриншот, сохранённый OpenAPI-файл и отчёт о соответствии не требуются.

В реализацию не входят типизация успешных ответов, новые маршруты,
собственный генератор и новый тестовый аппарат.
