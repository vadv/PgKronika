# Правила и семантика реестра

Этот документ описывает действующий контракт
[`kronika-registry`](../../crates/kronika-registry/README.ru.md). Расписание,
SQL, top-N и ротация сегментов принадлежат коллектору и не кодируются в
`TypeContract`.

## Нумерация

В коде идентификатор записывают как `C_SSS_VVV`:

```text
1_005_003
| |   |
| |   `-- VVV: версия схемы, 003
| `------ SSS: номер логического типа, 005
`-------- C: класс секции, 1
```

На диске это обычный `u32` со значением `1005003`. Части означают:

- `C` — класс секции;
- `SSS` — номер логического типа внутри класса, начиная с `001`;
- `VVV` — версия физической схемы и её смысла, начиная с `001`.

| `C` | `SectionClass` | Текущее состояние |
| ---: | --- | --- |
| `1` | `Snapshot` | Все зарегистрированные типизированные секции, включая stderr-события |
| `2` | `Event` | Класс распознаётся, зарегистрированных контрактов нет |
| `3` | `Dictionary` | `dict.strings` и `dict.blobs` кодируются отдельно от `registry()` |
| `10` | `Chart` | Класс распознаётся, зарегистрированных контрактов нет |

Класс идентификатора и `Semantics` являются разными свойствами. Например,
текущие типизированные события журнала имеют класс `1` и
`Semantics::EventStream`. Линтер не требует определённого сочетания класса и
режима сбора.

## Состав контракта

Один `TypeContract` содержит:

| Поле | Назначение |
| --- | --- |
| `type_id` | Выбирает точную схему и кодек |
| `name` | Объединяет версии одной логической секции при чтении |
| `semantics` | Описывает форму одного результата сбора |
| `columns` | Фиксирует порядок, физический тип, роль, допустимость `NULL` и необязательные ворота сбора |
| `sort_key` | Задаёт порядок строк перед кодированием |
| `identity` | Задаёт ключ временного ряда для разностей |
| `deprecated` | Оставляет старую схему доступной для чтения, когда её больше не записывают |

Контракт не содержит запрос, период запуска, лимит top-N, тайм-аут, правило
ротации или политику хранения.

## Режимы сбора

`Semantics` описывает тело, которое источник сформировал в одном запуске. Он не
доказывает, что источник был запущен по расписанию, что исходное представление
прочитано без ограничений или что конкретный сегмент содержит полные данные.

| Вариант | Что означает | Текущие примеры |
| --- | --- | --- |
| `SnapshotFull` | Тело содержит весь результат, который вернул модуль источника | Большинство `pg_stat_*`, секции ОС и cgroup |
| `ConditionalFull` | Полное тело появляется только при выполнении условия источника | `pg_locks`, `pg_stat_progress_vacuum`, `pg_vacuum_observation` |
| `EventStream` | Тело содержит события, замеченные за обработанный интервал | Типизированные stderr-события |
| `Changed` | Поддерживаемая модель изменившихся строк с `is_baseline` | Зарегистрированных контрактов сейчас нет |
| `OnChange` | Снимок записывается при изменении или периодическом обновлении | `pg_settings`, `os_mountinfo`, `os_topology` |

Отсутствие секции само по себе неоднозначно. Возможные причины: источник не
наступил по расписанию, условие `ConditionalFull` ложно, результат пуст,
произошла ошибка или сработал предел. Для вывода используйте сообщения
коллектора, пропуски считывателя и служебные секции полноты.

`collection_coverage` сообщает об усечении выбранных top-N источников.
`snapshot_coverage` описывает попытку получить многострочный снимок и его
происхождение. Эти секции не восстанавливают потерянные строки и сами по себе
не создают `Gap`: потребитель должен явно учитывать их.

## Роли и физические типы

| `ColumnClass` | Смысл | Интерпретация |
| --- | --- | --- |
| `Timestamp` | Обязательный `ts: Ts` снимка | Положение строки на временной оси |
| `Label` | Идентификатор или атрибут сущности | Может входить в `identity` |
| `Cumulative` | Накопительный счётчик | Приращение и скорость между допустимыми точками |
| `Gauge` | Мгновенное значение | Исходное значение без вычитания предыдущей точки |

`identity` не является отдельной ролью. Это список имён `Label`-столбцов. Если
список пуст, текущий считыватель использует `sort_key` без `ts`.

Поддерживаемые `ColumnType`:

```text
I8 I16 I32 I64
U8 U16 U32 U64
F32 F64
Bool
Ts
StrId
ListI32
```

`Ts` физически является `i64` в микросекундах Unix. `StrId` является `u64`,
который ссылается на байты в словарях сегмента. `ListI32` соответствует Arrow
`List<Int32>`. `Option<T>` делает столбец физически nullable; `NULL` в
обязательном столбце является ошибкой декодирования.

## Разности и ворота сбора

Для двух соседних точек одного `identity`:

- увеличение `Cumulative` даёт точное приращение и скорость за фактический
  интервал;
- одинаковое значение даёт настоящее нулевое приращение;
- уменьшение даёт `Reset`, а не отрицательную скорость;
- первая точка, разрыв времени и непригодный интервал остаются отдельными
  состояниями;
- `Gauge` возвращается без вычисления разности.

Некоторые накопительные столбцы имеют `gated_by`, например времена ввода-вывода,
зависящие от `track_io_timing`. Для интервала значение принимается, только если
последнее известное состояние ворот на его начало равно `true` и до конца нет
зафиксированного `false` или `NULL`. В остальных случаях результат —
`NotCollected`.

Ворота не отключают SQL и не меняют записанное значение. Они управляют
интерпретацией уже прочитанной разности. Смена настройки между двумя
наблюдениями не видна.

## Версии и совместимость

Один `type_id` соответствует одной точной Arrow-схеме. Новый идентификатор
нужен при изменении:

- имени, порядка, типа или допустимости `NULL` у столбца;
- `sort_key`, `identity`, `Semantics` или смысла существующего поля;
- ворот сбора;
- логической сущности, которую представляет тип.

Даже добавление nullable-столбца требует нового `VVV`. Старый и новый типы
могут иметь одинаковый `name`; тогда считыватель строит логическое объединение
столбцов, а отсутствующие поля старой версии возвращает как `NULL`.

Старый контракт нельзя удалять, пока поддерживается чтение созданных им PGM.
`deprecated = true` означает, что тип больше не записывают, но продолжают
декодировать. Сейчас у зарегистрированных контрактов этот флаг равен `false`.

Неизвестный `type_id` не становится понятным из схемы Parquet: прямое
декодирование возвращает `UnknownType`. Контейнер при этом можно открыть, а
незнакомую секцию — пропустить.

## Проверки

`lint_registry()` запускает `lint` и `lint_references`. Проверяются:

- уникальность `type_id`;
- существование столбцов `sort_key`;
- обязательный не-nullable `ts` для роли `Timestamp`;
- существование `identity` и роль `Label` у его столбцов;
- наличие `is_baseline` у `Changed`;
- положительный конечный `eps_abs` у оцениваемых ролей;
- существование и булев тип ссылок `gated_by`;
- допустимость ворот только для `Cumulative`;
- стабильный не-nullable строковый селектор переопределения ворот;
- согласованность ворот одного логического столбца между версиями.

Линтер не проверяет расписание, SQL, top-N, соответствие класса `type_id` и
`Semantics`, полноту Markdown или доступность контрактов сохранённых `type_id`.
Эти свойства проверяются код-ревью, тестами источника и обновлением
справочника в том же изменении.
