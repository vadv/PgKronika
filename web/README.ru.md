# Веб-интерфейс PgKronika

Интерфейс оператора: React-приложение, которое компилируется внутрь бинарника
`pg_kronika-web` и отдаётся офлайн с хоста базы данных. Сети во время работы
нет — всё, что нужно странице, едет внутри бинарника.

## Требования

- **Node 22**, зафиксирован в `.nvmrc` и в `engines` из `package.json`; CI
  читает тот же `.nvmrc`. На Node 24 и новее тесты падают: там появился
  глобальный `localStorage`, перекрывающий тот, что ставит jsdom, и
  `theme.test.ts` валится с `localStorage.clear is not a function`.
- **GNU tar** для упаковки тарболла с ассетами. В macOS штатный `tar` — это
  bsdtar, который не понимает `--sort=name`; `brew install gnu-tar` даёт
  `gtar`, и `Makefile` подхватывает его сам.

## Как UI попадает в бинарник

```
web/src/          vite build      bins/pg_kronika-web/static/   (в .gitignore)
      │  ───────────────────────▶            │
      │                                       │ tar --sort=name --mtime=@0
      │                                       ▼
      │                         bins/pg_kronika-web/static.tar.gz   (в git)
      │                                       │ build.rs
      │                                       ▼
      └──────────────────────────▶  OUT_DIR/static  →  rust-embed  →  бинарник
```

Результат сборки не хранится деревом — он давал диффы автогена в тысячи строк
на каждое изменение. Вместо этого коммитится один детерминированный тарболл:
одинаковые исходники дают одинаковый архив, поэтому файл ревьюится как
контрольная сумма, а не как содержимое.

**Изменение в `web/src/` не закончено, пока в том же коммите не выполнен
`make web-frontend`.** Иначе бинарник продолжает отдавать прошлый UI, а дифф
утверждает обратное. CI это сторожит: пересобирает тарболл и падает на любом
расхождении.

## Команды

| Команда | Что делает |
|---|---|
| `make web-frontend-check` | `tsc --noEmit`, `eslint --max-warnings 0`, `vitest run --coverage` |
| `make web-frontend` | `vite build` плюс детерминированная упаковка тарболла |
| `npm run dev` | Dev-сервер Vite, проксирует `/v1` на `127.0.0.1:8080` |
| `npm run demo:stub` | Статический стаб API на фикстурах — скриншоты без базы |
| `npm run demo:shot` | Puppeteer-скриншоты стаба в обеих темах |

Пороги покрытия живут в `vitest.config.ts`. Бутстрап и модули без поведения
(`main.tsx`, `i18n/index.ts`, `api/types.ts`) исключены из знаменателя:
оставить их — значит напрашиваться на фиктивные тесты ради цифры.

## Структура

- `src/api/` — HTTP-клиент и хуки TanStack Query, по модулю на эндпойнт.
- `src/state/` — состояние анализа, синхронизированное с URL. URL —
  единственный источник правды для `source`, `at`, `span`, `baseline`, `view`,
  `preset`, `focus`, `q` и `sort`, поэтому любой экран является ссылкой,
  которую можно переслать. Персональные настройки — тема, плотность, язык — из
  URL намеренно исключены.
- `src/components/` — панели.
- `src/design/` — токены и темы. Компоненты читают токены; захардкоженный цвет
  — это баг светлой темы, ждущий своего первого пользователя.
- `src/i18n/` — словари `ru` и `en`, паритет ключей проверяется тестом.
- `scripts/` — демо-стаб и скриншотный харнесс.

## Контракт данных

Формы ответов берутся из `bins/pg_kronika-web/openapi/`, который генерируется
из Rust-хендлеров и защищён от дрейфа гейтом в CI. UI читает этот контракт и не
выдумывает поля.

`src/api/schema.d.ts` генерируется из дерева OpenAPI через
`openapi-typescript` (`npm run codegen`, из корня репозитория —
`make web-codegen`); закоммиченный файл защищён от дрейфа гейтом в CI,
как и само дерево. `src/api/types.ts` лишь ре-экспортирует сгенерированные
схемы под стабильными алиасами — добавляй алиас туда вместо ручного DTO
или импорта `schema.d.ts` из компонентов. Вызовы идут через `apiGet`,
у которого путь и query-параметры проверяются по схеме на уровне типов.

Ошибки несут стабильный `code` и `params`; человекочитаемого сообщения на
проводе нет, и UI рендерит код через словарь i18n.
