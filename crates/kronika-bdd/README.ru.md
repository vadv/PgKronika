# kronika-bdd

[English version](README.md)

`kronika-bdd` — раннер интеграционных тестов, проверяющий поведение коллектора
и web на PostgreSQL 15, 16, 17 и 18. Nix поставляет серверные бинарники и
поддерживаемые форки `pg_store_plans`; Docker запускает тот же образ локально и
в GitHub Actions.

Раннер не входит в продуктовую поставку. Обычный `cargo test --workspace` не
поднимает PostgreSQL на хосте.

## Жизненный цикл сценария

Матрица PostgreSQL поднимается один раз на процесс. Сценарии выполняются
последовательно: создают отдельную базу, открывают именованные сессии
`tokio-postgres`, воспроизводят состояние из feature-файла, запускают коллектор
до готового сегмента и сравнивают декодированные строки с явным ожиданием или
независимым оракулом PostgreSQL. Cleanup закрывает сессии и удаляет состояние
сценария.

Пропущенный шаг Cucumber считается ошибкой. Отчёт об ошибке содержит нужную
секцию, значения оракула, вывод коллектора и журналы PostgreSQL. Matrix smoke
дополнительно сверяет заявленный major с `server_version_num`.

## Команды

Раннер модульных тестов (без PostgreSQL):

```sh
cargo test -p kronika-bdd
```

Полная Docker/Nix-матрица из корня:

```sh
DEBUG=1 make test-bdd
```

Одно tag-выражение:

```sh
DEBUG=1 make test-bdd TAGS=@pg_log
```

`TAGS` валидируется и передаётся как `--tags`. `DEBUG=1` включает подробный
вывод. Нужны демон Docker и Buildx; Nix на хосте не требуется. Кэш и CI описаны
в [`../../docs/testing.md`](../../docs/testing.md).

## Окружение раннера

Nix-образ задаёт:

- `KRONIKA_PG_MATRIX` — список `major=bin_dir` через `;`;
- `KRONIKA_COLLECTOR_BIN` — путь к коллектору;
- `KRONIKA_FEATURES` — каталог feature-файлов.

Запуск бинарника вне этого окружения обычно завершается ошибкой
`KRONIKA_PG_MATRIX is not set`. Используйте `make test-bdd`, если не
разрабатываете хелпер образа.

Правила feature-файлов и оракула — в
[`../../docs/bdd-testing-guide.md`](../../docs/bdd-testing-guide.md). При
расхождении со старыми проектными примерами каноническими считаются текущие
feature-файлы и шаги.
